# Автоматическая выдача подписок

Сервис для Android FlClash: пользователь вводит имя/email и получает одну
VLESS-подписку mihomo и связанную общую ссылку WDTT. Подтверждения email, паролей,
лимита устройств и сессий нет. Знающий логин получает ту же пару доступа.
Старые профили приложения не обращаются к этому сервису.

## Домашняя установка

Сервис развёрнут на `192.168.1.239`, публичный API —
`https://hub.everens.online/api/v1/provision`. Используются API клиентов 3x-ui 3.11,
инбаунд VLESS №2 с внешним портом 443 (внутренний 8443) и общий доступ WDTT.
Служба `everensprox-provisioning` включена в автозапуск. Секретная конфигурация
хранится в `/etc/everensprox-provisioning`, база — в `/var/lib/everensprox-provisioning`.
Резервная копия до установки — `/root/everensprox-provisioning-backup-20261123-193359`.

Для Reality-инбаунда №2 включён `reality_mlkem_inbound_ids: [2]`: актуальный Xray
проверен с Chrome fingerprint и X25519MLKEM768 в mihomo. Без этого параметра
mihomo может получать `REALITY authentication failed`, хотя Xray-клиент с теми
же UUID и ключами подключается. Исправление приходит через обновление подписки;
URL подписки, UUID и WDTT-доступ не меняются.

Проверены повторная выдача, загрузка подписки с другого компьютера, сохранность
старых клиентов и HTTPS-трафик через каждый из выданных транспортов VLESS и WDTT.

## Установка на домашний сервер

Требуются Linux/systemd, Python 3.10+, 3x-ui с Bearer API и WDTT Plus с
административным Unix-сокетом и поддержкой `create --shared`.
Изменения приложения сами по себе не устанавливают сервер.

1. Передайте этот каталог на сервер. Запустите `sudo python3 client-provisioning/install.py`:
   первый запуск создаст `/etc/everensprox-provisioning/config.json` и остановится.
2. Заполните конфигурацию. `public_url` — `https://hub.everens.online`;
   `public_host` — доступный клиентам адрес VLESS; `wdtt_host` — адрес UDP WDTT.
   При CDN для HTTPS адреса туннелей должны указывать на сервер напрямую.
3. Задайте URL 3x-ui с действующим префиксом панели и отдельный файл
   `panel-auth.json` вида `{"token":"SERVER_API_TOKEN"}`. Дайте токену права
   чтения инбаундов и добавления клиентов. В файл `wdtt-password` запишите
   административный пароль WDTT. Оба файла должны иметь права `0600`.
   `wdtt_hashes` берутся из действующей рабочей WDTT-ссылки.
   Для 3x-ui 3.11 используется `client_api: "universal"`: JSON-методы
   `clients/add` и `clients/{email}/attach`. Для старых панелей с методом
   `inbounds/addClient` явно укажите `client_api: "legacy"`.
4. Рекомендуется явно перечислить клиентские VLESS-инбаунды в `inbound_ids`.
   Пустой список включает все включённые VLESS-инбаунды, кроме слушающих loopback.
   `inbound_hosts` позволяет задать отдельный публичный адрес по строковому ID.
   `inbound_ports` задаёт внешний порт по ID, если nginx принимает 443 и передаёт
   соединение на локальный инбаунд 8443: например, `{"2":443}`. Локальный порт
   самого инбаунда и существующие ссылки при этом не меняются.
   В `reality_mlkem_inbound_ids` перечислите только Reality-инбаунды сервера,
   проверенные с X25519MLKEM768. По умолчанию список пуст для совместимости
   со старыми Reality-серверами.
   Поддерживаются TCP/raw без HTTP-маскировки, WS, gRPC и XHTTP; TLS и Reality.
   Проверьте совместимость настроек транспорта с mihomo до публикации.
5. Повторите установку. Сервис слушает **только 127.0.0.1:19091**.
   Root нужен для доступа к существующему закрытому административному сокету WDTT;
   systemd ограничивает запись каталогом состояния. Пароли не передаются через argv.
6. Добавьте `nginx.conf.example` в существующий HTTPS virtual host домена,
   сохранив его сертификат. Проверьте `sudo nginx -t`, затем перезагрузите nginx.
   Не публикуйте напрямую порт сервиса, панель 3x-ui и административный WDTT.
7. Проверьте `curl --fail http://127.0.0.1:19091/health` и
   `sudo systemctl status everensprox-provisioning`. С тестовым логином выполните:

```sh
curl --fail https://hub.everens.online/api/v1/provision \
  -H 'Content-Type: application/json' --data '{"login":"test-client"}'
```

Ответ содержит секретные ссылки. Проверяйте их локально, не копируйте в Git или
журналы. Nginx для этих URL отключает access log; при наличии внешнего прокси
аналогично исключите записи путей подписок. Rate limit — 60 запросов в минуту
на IP, а не ограничение устройств. При массовом добавлении за одним NAT повторите
запрос позднее. Сервис обслуживает до 16 запросов одновременно.

## API и восстановление

- `POST /api/v1/provision`, JSON `{"login":"имя или email"}`.
- Ответ: `account_id`, нормализованный `login`, `subscription_url`, `wdtt_link`.
- `GET /api/v1/subscriptions/<token>` — JSON-конфигурация, совместимая с YAML mihomo.
- `GET /api/v1/subscriptions/<token>/metadata` — комплект ссылок для обновления клиента.
- Ошибки: 400 — неверный запрос; 404 — неизвестная ссылка; 429 — частые запросы;
  503 — недоступность зависимостей или конфликт существующих настроек.

Токен ссылки генерируется случайно. Логин сравнивается без учёта регистра, пробелы
по краям удаляются; длина 1–254 символа, управляющие и невидимые служебные символы
запрещены. Название профиля хранится только в приложении.

Ключи сохраняются в SQLite **до** обращения к внешним системам. Повтор после
частичного сбоя находит уже созданные записи. Каждый запрос выдачи/обновления
проверяет обе стороны и добавляет недостающие VLESS-инбаунды. Существующие UUID,
subId, сроки и квоты не сбрасываются; конфликт нескольких VLESS-подписок одного
логина требует ручного разрешения. Отключённые/истёкшие доступы не активируются.
Персональный WDTT-доступ не меняется: создаётся отдельный общий доступ с тем же
названием. Общий доступ с подходящим названием переиспользуется.

Количество устройств на общей WDTT-ссылке не ограничивается. Серверные настройки
ёмкости базы WDTT (`max-passwords`) относятся к числу разных доступов, а не
устройств одного логина; при исчерпании ёмкости администратор увеличивает её.

## Обновление и резервное копирование

Не запускайте bootstrap-установщик поверх установленного кода. Остановите только
`everensprox-provisioning`. В закрытый root-каталог с правами `0700` скопируйте
`/etc/everensprox-provisioning`, `/var/lib/everensprox-provisioning`,
`/opt/everensprox-provisioning` и systemd unit. Замените `backend.py` и `server.py`
согласованным комплектом, при необходимости unit, выполните `daemon-reload` и
запустите сервис. Проверьте health и повторную выдачу существующему тестовому
логину: ссылки должны сохраниться. При ошибке остановите сервис и верните код,
unit и SQLite из одной резервной копии. Сам Xray и WDTT не останавливайте.

SQLite содержит секретные ссылки. Потеря SQLite меняет публичные токены подписок,
даже если клиенты сохранились в 3x-ui/WDTT, поэтому резервируйте базу обязательно.

## Проверки

```sh
python3 -m unittest discover -s client-provisioning -v
```

Android-клиент использует `https://hub.everens.online` по умолчанию. Другой HTTPS
origin задаётся при сборке через `--dart-define=PROVISIONING_URL=https://example.org`;
API должен находиться в `/api/v1/`. Импорт/экспорт профилей сохраняет признак
управляемого профиля, транспортные переключатели и логин внутри overrides.
