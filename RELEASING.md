# Выпуск Android

Источник обновлений приложения: `noman17rus/EverensProx`. В этом репозитории
публикуются только APK для Android и `SHA256SUMS`.

## Ветки и релизы

- `master` — только проверенные релизы. Каждый выпуск остаётся здесь коммитом и
  тегом (`v0.9.4`, `v0.9.5`, ...); напрямую в `master` не разрабатываем.
- Текущая рабочая ветка версии — `0.9.6`. В ней делаются изменения, тесты и сборка.
- После проверки рабочая ветка сливается в `master`:
  `git switch master`, `git merge --no-ff 0.9.6`, `git push origin master`.
  Затем создаётся следующая ветка версии, например `0.9.7`.
- Релизный тег ставится на коммит в `master` после слияния, а APK и `SHA256SUMS`
  прикладываются к GitHub Release.
- `main` оставлен как историческая ветка и не используется для новых релизов.

## Версия и имена файлов

Для версии `0.9.6+2026114604` тег релиза — `v0.9.6`. Один и тот же APK ARM64
публикуется под именами `FlClash-0.9.6-android-arm64-v8a.apk` (для клиентов 0.9.4/0.9.5)
и `FlClash-0.9.6-android-arm64.apk` (новый формат upstream). Имя `FlClash`
сохранено для совместимости со встроенным механизмом обновления.

Текущая сборка 0.9.6 — единый ARM64 APK без `--split-per-abi`, поэтому итоговый
`versionCode` равен базовому `2026114604`. Он выше versionCode прошлых 0.9.4
(`2026114401`) и 0.9.5 (`2026114502`), поэтому установка идёт поверх с сохранением
данных. Для следующих выпусков можно снова использовать `--split-per-abi`, но
помните, что Flutter добавляет смещение ABI `2000`; всегда проверяйте итоговый
`versionCode` в готовом APK.

Описание WARP для пользователей: [WARP.md](WARP.md).
Текст релиза: [RELEASE-0.9.6.md](RELEASE-0.9.6.md).

Следующий выпуск должен увеличивать и `X.Y.Z`, и Android `versionCode` в
`FlClash/pubspec.yaml`. Одна лишь смена `versionCode` не запускает проверку обновления.
Публикуйте стабильный релиз, без признаков draft и prerelease.

## Проверки и сборка

1. Клонируйте репозиторий с `--recurse-submodules`.
2. Подготовьте Flutter и нативные зависимости по `FlClash/.agents/commands.md`.
3. Выполните `flutter pub get`, `flutter analyze --no-fatal-infos` и тесты
   `test/common/app_update_test.dart`, `test/common/request_test.dart`,
   `test/widgets/update_dialog_test.dart` из каталога `FlClash`.
4. Для полной сборки нативных компонентов используйте `dart tool/package.dart android --arch arm64`.
   Отдельный APK ARM64 собирается через
   `flutter build apk --release --split-per-abi --target-platform android-arm64`.
   Публикуйте только те ABI, которые действительно собраны и проверены.
5. Подпишите APK тем же ключом и проверьте сертификат через `apksigner verify --print-certs`.
6. Создайте `SHA256SUMS` в формате `<sha256>  <точное имя APK>` со строкой для
   каждого имени APK. Опубликуйте тот же список как `FlClash-0.9.6-SHA256SUMS`
   для нового механизма обновления upstream. В следующих выпусках сохраняйте оба
   формата APK и контрольных сумм для перехода с установленных версий.
7. Отправьте изменения в форки, закрепите подмодули, создайте тег основного
   репозитория и приложите APK вместе с `SHA256SUMS` к GitHub Release.

## Подпись текущей сборки

В `v0.9.6` сохраняется подпись предыдущих APK — Android Debug,
идентификатор `com.follow.clash.dev`. Это release-сборка Flutter с существующим
ключом подписи, а не отдельный production-ключ. SHA-256 сертификата:

```text
06d3d85f670fd4ef9d8cefe118669d3915092a36bbcf354466496288c00325e3
```

Ключ и пароли не должны попадать в Git или вложения релиза. Сохраните ключ отдельно:
потеря либо смена ключа помешает устанавливать обновления поверх текущего приложения.
Для перехода на отдельный production-ключ потребуется спланировать установку и перенос данных.

Локальный APK этой версии использует Rust/SQLite из официального upstream APK
FlClash 0.9.4 ARM64 (SHA-256
`86fb6f66b5f4d36a3423adeadca625b147da0e782400b6af69aafe58c603a947`).
Rust-исходники в стабильной ветке upstream совпадают с тегом 0.9.4.
Go-ядро, WDTT, ByeDPI и Android-компоненты собираются из текущего рабочего
проекта на Flutter 3.50.0. Локальные инструменты и кеши находятся в `.build/`
и не входят в Git.
